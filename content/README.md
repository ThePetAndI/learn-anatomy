# Формат контента

Весь учебный материал лежит здесь в JSON, отдельно от кода. Можно дописывать руками:
дев-сервер подхватит изменения сам, сборка — после `npm run build`.

Проверить файлы:

```bash
npm run validate:content
```

Проверка запускается и перед каждой сборкой, и в тестах. Она ругается на дубликаты id,
битые ссылки, пустые поля, лишние поля, неверные символы, похожие термины в одном уроке
и на повторение того, что ещё не вводилось. Правила проверки — `src/data/validate.ts`.

## Файлы

```
content/
  course.json      разделы и уроки по порядку
  terms/*.json     термины; файлы читаются все подряд, имя роли не играет
  rules.json       карточки-правила: как образуются названия, латинские корни
  paths.json       пути по порядку: звенья пути крови или импульса
  diagrams/*.svg   схемы; формат — ниже
  REVIEW.md        всё, что помечено "verified": false; собирается npm run review
```

## Термин

```json
{
  "id": "t_superior_vena_cava",
  "en": "superior vena cava",
  "ru": "верхняя полая вена",
  "also": { "en": [], "ru": [] },
  "plural": "venae cavae",
  "kind": "vein",
  "system": "circulatory",
  "confusableWith": [],
  "about": "Короткая широкая вена. Собирает кровь от верхней части тела и впадает в правое предсердие.",
  "relations": {},
  "diagrams": [],
  "audio": null,
  "source": "TA2; Сапин, т. 2",
  "verified": true,
  "note": ""
}
```

| поле | обязательное | что значит |
|---|---|---|
| `id` | да | `t_` + латиница в нижнем регистре, цифры, `_`. Уникален. **Не менять** после того, как курс проходили: к нему привязан прогресс |
| `en` | да | Английский термин по TA2 и Gray's Anatomy, в нижнем регистре |
| `ru` | да | Русский термин, принятый в учебниках (МАТ, Сапин, Синельников), без калек |
| `also` | нет | Другие принятые названия: `circulatory system` у `cardiovascular system`. Засчитываются в ответах, видны на карточке |
| `plural` | нет | Неправильное множественное число по-английски: `atria`, `venae cavae` |
| `kind` | да | `artery` `vein` `vessel` (сосуд вообще, капилляр) `nerve` `muscle` `organ` `structure` (часть органа или кости: предсердие, клапан, отверстие) `concept` (понятие: круг кровообращения, артериальная кровь) |
| `system` | да | `circulatory`, `nervous` или `other` — для органов других систем (лёгкое, печень) |
| `confusableWith` | нет | id терминов, которые легко спутать с этим, если по названию этого не видно: `systemic circulation` ↔ `pulmonary circulation`. Пары вроде superior / inferior, artery / arteriole, afferent / efferent находятся сами |
| `about` | да | Одно-два предложения по-русски: что это и где. Кончается точкой. Показывается на карточке и после ошибки |
| `relations` | да | Связи с другими терминами, может быть `{}`. Ключи ниже |
| `diagrams` | да | id схем из `diagrams/`, где есть этот термин; первой — самую общую, она на карточке. Может быть `[]` |
| `audio` | да | Задел на произношение, пока `null` |
| `source` | да | Откуда взято |
| `verified` | да | `false`, если есть сомнения, — тогда обязательно `note`, и строка уйдёт в REVIEW.md |
| `note` | нет | Пояснение для проверяющего |

**Связи** — id терминов:

| ключ | значение |
|---|---|
| `branchOf` | ветвью чего является: `"t_pulmonary_trunk"` |
| `supplies` | что кровоснабжает — о чём можно спросить: `["t_kidney"]` |
| `suppliesPart` | что кровоснабжает лишь частью: у чревного ствола — тонкая кишка (начало двенадцатиперстной). Об этом не спрашивают, но и неверным вариантом такой орган не ставят |
| `drainsTo` | куда впадает (вены) |
| `innervates` | что иннервирует — о чём можно спросить (нервы) |
| `innervatesPart` | что иннервирует лишь частью — как `suppliesPart` |

Связь указывается, только если она точна. «Впадает в предсердие», пока в курсе нет правого
и левого предсердий, — неточно, такую связь не пишем.

## Правило

```json
{
  "id": "r_pulmonary",
  "title": "Lung, но pulmonary",
  "body": "Первый абзац.\n\nВторой абзац.",
  "examples": [{ "en": "lung", "ru": "лёгкое" }],
  "source": "Gray's Anatomy",
  "verified": true,
  "note": ""
}
```

Абзацы в `body` разделяются пустой строкой (`\n\n`).

## Урок

```json
{
  "id": "l_circ_veins",
  "title": "Вены",
  "rules": ["r_direction"],
  "terms": ["t_vein", "t_atrium", "t_superior_vena_cava"],
  "review": []
}
```

| поле | что значит |
|---|---|
| `terms` | Новые термины по порядку знакомства. Обычно 3–5, больше 6 нельзя. Каждый термин вводится в курсе один раз |
| `review` | Термины прошлых уроков, которые урок повторяет обязательно. Урок без `terms` — урок-повторение |
| `rules` | Карточки-правила перед первым заданием |
| `paths` | Пути из `paths.json`, которые урок даёт расставить. Все звенья к этому уроку должны быть знакомы |

Похожие термины (superior / inferior vena cava, common / internal carotid) в одном уроке
новыми быть не могут — проверка не пропустит. Рядом они стоят только в уроке-повторении,
когда оба уже знакомы: там они специально идут неверными вариантами друг к другу.

Остальные задания сборщик (`src/lesson/build.ts`) подберёт сам: «Что это?», «Как
по-английски?», «Напиши по-английски», пары, повторение прошлого. Перед первым заданием на
незнакомый термин он всегда ставит его карточку.

## Схема

Файл `diagrams/<id>.svg`, id вида `d_slug`. Рисуется руками; подписей в файле нет —
названия на двух языках приложение берёт из терминов.

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 360 460" data-diagram="d_heart">
  <title>Сердце в разрезе (схема)</title>
  <g data-term="t_aorta">
    <path class="hit" stroke-width="48" d="M198 236C196 204 ..."/>
    <path class="vessel-oxy" stroke-width="26" d="M198 236C196 204 ..."/>
  </g>
  <g data-term="t_right_atrium" data-hit="area">
    <path class="cavity-deoxy" d="M96 146C90 160 ..."/>
  </g>
</svg>
```

Правила (проверяются `npm run validate:content`):

- **Вид спереди**, правая сторона тела — слева на рисунке. Порядок элементов в файле —
  порядок слоёв: что дальше в файле, то ближе к зрителю. Так рисуется «спереди — сзади»:
  лёгочный ствол впереди аорты, правая лёгочная артерия позади верхней полой вены.
  Тест `tests/diagrams.test.ts` проверяет стороны и этот порядок.
- **Каждая структура — группа `<g data-term="...">`**. Группа может быть контейнером без своей фигуры — аорта из восходящей части, дуги и нисходящей. Один термин может стоять на
  нескольких группах (оба предсердия у общего термина `t_atrium`). Группы можно вкладывать:
  камеры — в сердце, капилляры лёгкого — в лёгкое. «Найди сердце» засчитывает нажатие на
  любую его часть, а в «Что подсвечено?» вложенные друг в друга термины не ставятся
  вариантами друг к другу.
- **Зона нажатия** не меньше 44 px на телефоне. Схема в полный рост занимает 335 px,
  поэтому для ширины viewBox 360 это 48 единиц. Тонкий сосуд — невидимый дубль пути
  `class="hit"` с `stroke-width` не меньше нормы; маленькая фигура — `class="hit hit-area"`
  (круг или прямоугольник); площадь, которую и так легко нажать, — `data-hit="area"` у группы.
- **Цвет — классами**, без `fill`, `stroke`, `style`. Цвет по крови, как в атласах:
  `-oxy` — красный (богатая кислородом), `-deoxy` — синий. Поэтому лёгочный ствол синий,
  лёгочные вены красные.

| класс | что |
|---|---|
| `vessel-oxy`, `vessel-deoxy` | сосуд — линия, толщина в `stroke-width` |
| `cavity-oxy`, `cavity-deoxy` | полость: камера сердца |
| `muscle`, `apex`, `septum` | мышца, её участок без контура, перегородка (линия) |
| `organ` | орган другой системы: лёгкое |
| `bed`, `cap` | капиллярное русло: фон и сеть |
| `valve`, `valve-ring` | створки клапана и его кольцо |
| `outline` | контур тела или органа-ориентира, без подписи |
| `landmark` | ориентир пунктиром: диафрагма, ключица, паховая связка |
| `line` | тонкая линия: петли кишки |
| `tube` | трубчатый орган — толстая кишка; толщина в `stroke-width` |
| `groove` | борозда на поверхности органа |
| `node`, `conduct` | проводящая система сердца: узлы и пути |
| `behind` | добавочный класс: сосуд или нерв в глубине — пунктиром |
| `nerve` | нерв — жёлтая линия |
| `ring` | кольцевая мышца: круговые мышцы глаза и рта |
| `zone-1`, `zone-2`, `zone-3` | фон без подписи: зоны кожи трёх ветвей тройничного нерва |
| `hit`, `hit-area` | невидимые зоны нажатия |

Термин на схеме ⇔ id схемы в его `diagrams`: проверка ругается на расхождение в любую
сторону. Первая схема в `diagrams` показывается на карточке термина и в первых заданиях
на него — ставьте первой самую общую.

## Раздел

```json
{ "id": "s_heart", "system": "circulatory", "title": "Сердце", "lessons": [] }
```

Раздел без уроков виден в курсе с пометкой «готовится».

`"relations": true` у раздела включает в его уроках вопросы «Что кровоснабжает <артерия>?» и «Какая артерия кровоснабжает <орган>?», а для нервов — «Что иннервирует <нерв>?» и «Какой нерв иннервирует <мышцу>?». По SPEC они — с середины курса. Ответ берётся из `supplies`; неверные варианты — знакомые органы вне бассейна артерии (с учётом её ветвей и `suppliesPart`) или знакомые артерии, никак не связанные с органом, включая предков по `branchOf`.

## Путь по порядку

```json
{
  "id": "p_right_heart",
  "title": "Кровь через правые отделы сердца",
  "steps": ["t_superior_vena_cava", "t_right_atrium", "t_tricuspid_valve", "t_right_ventricle"],
  "source": "Сапин, т. 2",
  "verified": true,
  "note": ""
}
```

От 3 до 7 звеньев, без повторов, подряд — без пропущенных звеньев: если между двумя терминами есть сосуд, которого нет в курсе, путь на нём обрывают. Путь даётся уроком через его поле `paths`.
